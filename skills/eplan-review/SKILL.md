# 审查契约

审查不是「再看一眼图」。它是一次有输入、有判据、有放行条件的判定。

## 放行条件

三条全部满足才允许交付，缺一条就是没画完：

1. `validate` 的 `verdict` 不是 `fail`。
2. **意图层零差异**：器件不缺不多、标识唯一或已说明为何重名、每条连接要么被红线证实要么标为未接。
3. 成品图亲自看过，且 style 类未对齐项已在回复里列明。

## 输入

审查要看三样东西，缺哪样说明还没到审查阶段：

- **意图清单**：开工前写的那份（器件 N 个、连接 M 条、页名）。没有它就没有判据，只能凭感觉。
- **成品图**：`page_inspect(format="image", width=2000)` 或 `present` 渲染出来的那张。
- **参考图**：用户给了才有；没给就只审意图与规范，不做「像不像」的判断。

## 差异分类

每条差异都必须落在下面两类之一，**不允许不分**：

| 类别 | 内容 | 处理 |
|---|---|---|
| `intent` | 器件多/缺、标识错、引脚接到错的网络、该连的没连、页结构不符 | 一律必修，一条都不能放行 |
| `style` | 位置偏移、间距疏密、标签在左还是右、字号、线宽、配色、留白 | 不影响读图就放行，影响就在回复里说明 |

判不准时按 `intent` 处理——把风格问题升级成必修只是多花一点时间，把电气问题降级成风格会交出去一张错的图。

## 怎么审

### 机器能判的部分先判

- `validate` 的 `errors` / `warnings` / `geometry`：这是程序给出的，不要用眼睛去替代。
- `validate` 的 `expectDevices`：事先把器件清单传进去，它会直接告诉你缺了谁、多了谁。**能用这个就别靠看图数数。**

### 剩下的再用眼睛

写一段程序，把成品图路径交给审查子代理（空上下文，它只看得到图和你给的清单）：

```
tools.subagent({
  description: 'EPLAN 页审查',
  prompt: [
    '你是 EPLAN 图纸审查员。只对照给定材料，不猜、不推断设计意图。',
    `意图清单：${intentText}`,
    `成品图：${renderedPath}`,
    referencePath ? `参考图：${referencePath}` : '（没有参考图，不做像不像的判断）',
    '逐条核对意图清单里的每个器件与每条连接；再检查文字是否压元件、标识是否重复。',
    '每条差异标 category=intent|style，并给出证据（在图的哪个位置、看到了什么）。',
    '不要提改进建议，不要评价美观。',
    '输出 JSON：{"verdict":"pass|fail","intent":[{"where":"","expected":"","actual":"","evidence":""}],"style":[{"where":"","expected":"","actual":""}]}',
  ].join('\n'),
})
```

`tools.subagent` 不在 SDK 里时，不要反复重试：自己按同一份清单逐条核对图和 validate 输出，并在回复里说明「本轮为人工核对，未用审查子代理」。

## 结果怎么用

1. `intent` 非空 → 修，修完重新 `validate` + 重新出图 + 重审。**不要在一次审查后连改三项却不复核。**
2. `style` 不影响读图 → 放行，在回复里列一句「还有 X 处位置差异未对齐」。
3. 子代理说 `fail` 但你核对后认为它看错 → 以图和 `validate` 为准，不要为了迎合它改图；在回复里说明这次分歧和理由。

## 常见的不合格审查

| 做法 | 为什么不合格 |
|---|---|
| 只说「看着差不多」 | 没有对照意图清单，等于没审 |
| 只报 severity（high/medium/low） | 不分 intent / style，风格问题被当成必修，电气问题可能被降级 |
| 用眼睛数器件 | 数错的概率比机器高；能 `expectDevices` 就别用眼睛 |
| `validate` 通过就说合格 | `validate` 只看规范与几何，不知道这一页该有哪些器件 |
| 审一次之后连改多处不再复核 | 改完的状态没人看，等于没审 |
